# L1: the order book and matching

This week you start with the basics of the exchange: matching. Orders, cancels and
modifies come into the matching engine, and you write the code that updates the book
and returns the events that result.

- **Yours:** matching, the functions listed below. Each one says what it must do, and
  the comment in the code itself helps you start.
- **Given:** the order book, which keeps the orders in price-time priority. Use what it
  offers; you don't need to worry about the internals. Its tests pass from the start.
- **Start small:** get a few tests green early, and leave the modify for last; it
  builds on the rest.
- **Power prices go below zero.** Every price and quantity is a fixed-point number with
  its scale in its name: `price_e2` in hundredths of a euro (so 123 means €1.23/MWh),
  `quantity_e1` in tenths of a MW (so 98 means 9.8 MW).
- **Optional:** fill-or-kill, an order that trades all of its quantity at once or none
  of it. It is one more function and a step in `match`, which `match`'s docstring
  describes; "This week's tests", below, says how to enable it.

## The bigger picture

Over this course you build a small exchange: a venue where participants trade one hour
of power with each other, as on the XBID markets. Upcoming weeks will add everything
that surrounds it: orders arriving over the network, market data going out, surviving
failures, risk checks, and speed. All of it rests on this week.
Matching is where the market's rules live: who trades with whom, at what price, in
which order. Everything else either brings orders to it or reports what it decided.

Nothing leaves matching but events. Its three functions (match, cancel, modify) change
the book they're given and return what happened as events: plain descriptions such as
a trade or an order resting. Matching itself sends no messages and keeps no records;
other parts of the exchange turn those same events into messages to the participants,
the public market data, and the venue's record of every order. That also makes
matching easy to test: a book, an incoming order, and the events you expect.

Matching has no clock and reads nothing from outside, so the same book and the same
orders always give the same events. That sounds like a detail, but it means a whole
day on the exchange can be replayed exactly, and later weeks rely on that.

The code you get splits the work the same way. The book keeps the orders in priority
and refuses to cross, but knows nothing about the market's rules: those are matching's,
and that is why matching is yours. The events and their builders are given, so your
code is about decisions, not bookkeeping.
